# PY股票AI操作盘

可验证股票研究助手，使用确定性评分与证据核验。按数据质检、财务分析、信号校准、解释与审核四个工作区组织流程。默认样本均为虚构数据，页面不提供实时行情，不自动交易。

## 使用流程

1. **数据质检**：导入1–5000条JSON对象（最多2MB）。检查格式、重复版本、缺失财务字段、金额口径、可获得时点及资产负债勾稽。所有重复记录都会标记，不会保留第一条作为默认真值。原始JSON与修正表单默认折叠。
2. **财务分析**：显示证券、报告期、净利率、现金利润比和负债率。财务字段齐全但缺少行情或事件字段时，仍显示财务指标，完整评分保持不可用。通过财务校验的修正可保存，不要求虚构市场字段。修正前会核对原始记录是否已被更换。
3. **信号校准**：导入单标的历史信号与个股/基准收益，调整入选阈值、成本与年化频率，实际计算收益、回撤、波动、夏普和历史VaR。
4. **解释与审核**：规则计算的结构化证据可以提交给已配置的大模型；输出进入人工审核。四维评价、逐条来源、原始证据摘录及验收答案完成后才能批准和导出训练样本。回答、证据、数据、分析时点或权重变化均会使既有批准失效。

导入数据与审核内容保存在页面内存，刷新前请导出。供应商密钥仅放在服务端，访问口令只保存在页面内存，不进入导出文件。论文、商业数据库或企业数据的本地测试文件不属于仓库公开样本。

## 数据约定

财务记录使用 `code, name, period, revenue, netProfit, operatingCash, assets, liabilities, currency, unit, basis, asOf, source`。`period` 如 `2024-Q4`；Q4全年累计和第四季度单季必须通过 `basis` 区分。金额字段统一币种和单位。营业收入不能替换成营业总收入；合并净利润不能替换成归母净利润。

完整评分还需 `pe, return20d, eventScore`。收益为小数，事件分数为0–100。`publicationDate` 可选，支持YYYY-MM-DD或带时区ISO时间。`asOf` 为实际可获得日期，不应把下载时间当成历史披露时间。缺失披露时间会提示历史点时验证不可用。

`equity` 可选，用于资产减负债减权益的勾稽。默认舍入容差为0.0002亿元，对应2万元或20000元；其他单位不自动猜测容差。核验标记不等于原件事实核验。

同比比较使用上年同季度，且币种、单位、期间口径一致。基期非正时不计算常规百分比增长。同业中位数至少需要三家其他独立企业；存在歧义的重复版本不参加比较。当前不自动挑选“最新重述版本”。

## 数学口径

- 净利率 = 合并净利润 / 营业收入（营收为正）。
- 现金利润比 = 经营现金流量净额 / 合并净利润（净利润为正）；亏损时显示不适用。
- 负债率 = 合并负债 / 合并资产（资产为正）。
- 演示质量因子 = 净利率×200 + 现金利润比×30；亏损时现金覆盖贡献为0。
- 演示趋势因子 = 50 + 20日收益×200。
- 演示风险保护因子 = 100 − 负债率×70 − max(0, PE−20)。
- 四因子限制在0–100，四项权重按总和归一化，综合分四舍五入。

因子映射、阈值和权重为未通过预测能力验证的启发式规则，不是概率、预期收益或适用于所有行业的估值模型。字段完整度仅为8个数值字段的非缺失比例，不代表可信概率。

### 历史校准

每行包含 `date, signalAsOf, score, assetReturn, benchmarkReturn`，可选 `code, benchmarkCode, tradeStatus`。日期严格唯一升序；信号必须在收益日期前已获得。真实停牌或不可成交记录需要专门执行模型，当前引擎会拒绝，不能直接当成正常交易。单次仅支持一只股票和一个基准。

入选时持有股票，否则持有现金。每期净收益 = (1−持仓变化×单边费率) × (1+持仓×个股收益) − 1。末期仍持仓时另扣平仓费。费用先从可投资资金扣除，避免简单减法少计上涨期成本。

累计净值从1开始复利；回撤基于含初始净值的日终峰值。基准为不扣交易费的买入持有。“收益差”是两个累计收益的百分点差；相对超额另按策略净值/基准净值−1计算。年化波动为样本标准差×年化期数平方根，夏普假定无风险利率0，零波动时不显示夏普。年化期数默认252，可显式调整。

历史VaR使用净收益样本5%最近秩分位的损失值；持仓日命中率按持仓日扣费净收益为正计数，不是逐笔交易胜率。至少30期可计算，但不足252期会提示小样本限制。它不是滚动训练、参数样本外验证或多资产组合风险模型。

## 模型配置

在服务端环境或不提交的 `.env.local` 设置：

```dotenv
RESEARCH_LLM_URL=https://your-provider.example/v1/chat/completions
RESEARCH_LLM_KEY=your-provider-key
RESEARCH_LLM_MODEL=your-model-name
RESEARCH_ACCESS_TOKEN=replace-with-a-random-token-at-least-16-characters
```

接口兼容Chat Completions。未配置返回503；口令错误返回401；每运行实例5秒请求间隔，30秒上游超时。仅在用户点击生成时发送证据到配置的模型服务。数据或证据在请求途中变化时，丢弃过期结果。规则模型负责数值，大模型不能直接修改评分。企业部署还需统一认证、权限、集中审计及分布式限流。

人工评估检查事实、计算、推理、风险四个维度。摘录必须能在原始证据中找到，断言必须对应验收答案原文；这些结构检查仍不能替代专业事实审核。待审核记录和已验收训练样本分别导出，人工批准不代表监管认证。

## 本地运行与验证

Node.js 22.13及以上：

```bash
pnpm install
pnpm dev
pnpm build
pnpm test
pnpm lint
pnpm exec tsc --noEmit
```

测试覆盖比例成本、重复版本、日期边界、缺失字段、同比、单标的校准及证据核验。仓库原有Cloudflare数据库和Worker类型声明在未生成运行时类型的环境中仍可能导致全量TypeScript检查失败。
